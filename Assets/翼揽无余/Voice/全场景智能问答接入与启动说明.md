## 每次开机后的快速启动

在一个新的 PowerShell 窗口中逐行执行：

```powershell
Set-Location "E:\BaiduNetdiskDownload\挑战杯"
$env:DASHSCOPE_API_KEY = "sk-替换成你自己的百炼密钥"
$env:YILAN_PROVIDER_PROFILE = "qwen"
$env:QWEN_MODEL = "qwen3.7-plus"
& ".\.venv\Scripts\python.exe" -B ".\scripts\run_voice.py" --host 0.0.0.0 --port 8765
```

看到 `WS 地址`、`健康检查` 和 `配置快照 ID` 后，不要关闭这个窗口。

另开一个 PowerShell 检查：

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/health"
```

返回 `status = ok` 才进入 Unity 或 PICO 测试。

## Unity 与 PICO 的地址

### 同一热点或同一 Wi-Fi

1. 在电脑执行 `ipconfig`。
2. 找到电脑当前网络的 IPv4，例如 `192.168.1.106`。
3. 打开 `Assets/Resources/Voice/PicoVoiceClient.prefab`。
4. 在 `Voice Client Bootstrap` 中把 `Ws Host` 改成这个 IPv4，端口保持 `8765`，路径保持 `/ws/voice/session`。
5. PICO 和电脑必须连接同一个网络；Windows 防火墙需要允许 TCP 8765。

网络或热点重新连接后，IPv4 可能变化；面板一直显示“未连接”时，先比较这里的 `Ws Host` 与 `ipconfig`。

### USB 调试方式

连接 PICO 后执行：

```powershell
adb devices
adb reverse tcp:8765 tcp:8765
```

此时 APK 中的 `Ws Host` 可以使用 `127.0.0.1`。重新插线或重启设备后要再次执行 `adb reverse`。

## 场景接入规则

运行时只保留一个 `PicoVoiceClient`，由 `Resources/Voice/PicoVoiceClient.prefab` 自动创建并跨场景保留。

- 需要显示机器人面板的场景：只放一个 `VoicePanelAnchor`。
- 不需要显示面板的场景：不要放 `VoicePanelAnchor`。
- 不要把 `PicoVoiceClient` 再拖入每个场景。
- 每个场景只能有一个 `EventSystem`。

`VoicePanelAnchor` 的位置、旋转、缩放和 `Panel Size` 都属于当前场景实例，可以逐场景调整；修改某个场景实例不会要求其他场景使用相同布局。运行时只查找当前激活场景中启用的 Anchor，避免加载多个场景时误绑定到别的场景。

## 流式回答

客户端会在 `session.start` 中请求 `answer-stream-v1`。后端接受后，候选回答会逐块写入现有滚动文字框；后端最终发送 `answer.display` 时，最终回答会替换候选内容。原始模型思考文本不会直接展示给用户，只显示“正在分析/生成/核对”等进度提示。

如果后端不支持该能力，客户端自动退回原来的最终回答模式，不影响基本问答。

## ASR 与 TTS

- Qwen3-ASR 已把航空热词作为 `prompt` 传入识别器，并增加 C919、歼-20、运-20、直-20、涵道比、主旋翼等术语。
- 当前复制环境使用 CPU 版 Torch，因此 Qwen3-ASR 配置为 `device: cpu`、`dtype: float32`；已完成本地模型预热验证，可以启动，但识别速度可能慢于 CUDA 版。
- 当前默认 TTS 仍是 `edge`，这是现阶段最稳妥的可运行配置。
- 后端已登记可选 `cosyvoice` 客户端适配器；只有本机 CosyVoice 3 服务和模型准备完成后才可把 `tts_provider` 切到 `cosyvoice`，否则保持 `edge`。缺少 CosyVoice 服务时不要强制切换。

## 打包前检查

1. Unity 控制台没有红色编译错误或 `Missing Script`。
2. Android 仅使用一种 Active Input Handling，避免选择 `Both`。
3. Internet 与麦克风权限可用。
4. ARM64、IL2CPP、PICO XR/OpenXR 配置保持项目当前已验证设置。
5. 后端健康检查为 `ok`。
6. 在编辑器连续完成两轮问答，确认取消后可回到 Ready。
7. 安装 APK 后先测试短问题，再测试长回答滚动与第二轮对话。
